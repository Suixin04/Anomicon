# 离线书架与副本更新验证

`fix/ux-offline` 冻结在 `5711febc98535bef7e594cb65a5009b82b879897`，Git tree 为 `0af91ca1049efdc5570cc3fdb66b42d6397c7e8e`。分支基线为 `04996ca327c8f2123ca8967bd9f5628aa1eda1ca`。首轮提交 `e66ebeb0573c515830427cd30b56c11a10a8da75` 实现书架读取与更新。`24bbc541f6204ce093536db1e0199d3f93226729` 修复子页重验与同址换图，本次修复图片格式改变后再次保存取回旧图的问题。

| 验证情形 | 分支实测结果 |
| --- | --- |
| 临时缓存 v2 与已保存 v1 并存 | 普通入口读到 v2。切到书架后读到 v1 正文和 v1 图片，HTML 请求数为 0。点击更新发出 1 次强制重验，阅读器和离线包均拿到 v2。 |
| 外页过期或请求失败 | 两种情况均报告“已保留原离线副本”。保存计数停在首次保存的 1 次，阅读器和永久副本仍显示 v1。条件请求确认的缓存响应可继续经兼容提取器完成更新。 |
| 正文在两层嵌入子页内 | 更新分别重验外页、中间页、正文页。正文页超时和回退过期内容时，关闭数据库、新建仓库读回 v1 外页、内文及配图字节。普通阅读仍能显示可用外页、嵌入链接或旧内文。中间页获条件请求确认、正文页返回 v2 后，重试并重开读到完整 v2。 |
| 同一地址替换配图 | v1 保存红色单像素 GIF，普通取图命中临时缓存。图源返回 404 时，显式更新失败，重开仍为 v1 和红图。图源恢复后，重试从同一地址取得蓝图，重开为 v2，文件字节与预期蓝图完全一致。图源共收到三次请求，分别对应首次保存、失败更新和重试。 |
| 同址 PNG 换 GIF 后移除并重新保存 | 旧实现复现：新版保存成功后，再次普通保存会将 69 字节的旧红 PNG 放回离线包。修复后，404 时普通取图和重开的 v1 都能读取红 PNG；重试更新取得 35 字节蓝 GIF。移除副本、重建图片缓存服务、普通取图并重新保存，再开库读回 v2 正文和逐字节一致的蓝 GIF。全过程只请求图源三次。 |
| 首次保存及补图 | 首次保存两图只下载一张时，副本记录缺 1 张。重试只请求缺图，重开后两图字节均正确。普通读者显示 v2 时，补图也取已保存的 v1 正文。 |
| 新地址的配图下载失败 | v2 缺 1 张图时显式更新报错。新建仓库读回 v1 正文及图片字节，图片可用后重试更新并读回 v2 正文和配图。 |
| 最后一次 SQLite 写入失败 | 对旧平铺格式与新版本目录分别运行。数据库触发器在 `INSERT OR REPLACE` 前拒绝发布。关闭连接、新建仓库并重开，原行全字段、正文、图片字节和缺图数 0 均通过断言。撤销触发器重试后指向 v2，旧正文路径被回收。 |

书架路由从同一条永久记录取得正文和配图。更新把确认过的正文和配图写到新目录，全部就绪后通过一次数据库写入发布，再回收旧版本。补图可从旧版本复用已有文件。普通阅读遇到正文子页失败或过期时仍可查看部分内容，派生正文缓存只记录已就绪的结果。

## 复跑

在离线分支工作树根目录，实测使用 ohpm 26.0.0.630、Hvigor 6.26.4 和 Node 24.19.0。同级 `tests` 工作树提供逐项核对 Hypium 报告的入口。

```sh
ohpm install --all --metadata_cache
node ../tests/scripts/test-host.mjs article
node --test features/article/src/test/OfflineVault.host.test.mjs
hvigorw --no-daemon --mode module -p module=phone@default -p product=default default@CompileArkTS
node ../tests/scripts/test-host.mjs catalog
```

- **正文 Hypium 51/51**。本次逐项核对 51 条成功记录，入口退出 0。
- **磁盘与 SQLite 7/7**。跨格式换图用例在上一版运行时单独失败，修复后七例全部通过。用例执行生产正文网关、图片缓存服务和永久仓库。主机适配层提供受控的 HTML 与图片响应、ImageKit 接口、文件系统和 SQLite。
- **手机端 ArkTS 编译通过**。分支 `git diff --check` 通过。
- **附加图鉴 Hypium 35/38**。3 个 `CachedArticleRepo` 用例均在预览器的 `ScpWikiUrlPolicy.normalizePageUrl` 报“`SCP 页面地址无效`”。测试组在相同基线复现了对应的三例，并在其分支补齐预览器 URL 夹具，见[测试分支验证记录](tests.md)。合并后的全量结果由集成验收核实。

设备集成待验项目包括实际点击书架、ArkUI 配图显示、系统图像解码、进程终止后再打开，以及真实 ArkData 的写入行为。
